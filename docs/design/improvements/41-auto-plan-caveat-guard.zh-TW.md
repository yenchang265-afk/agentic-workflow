# 41 — Auto-plan 遇到計畫警示就拒絕自動過閘

**狀態：已實作。**

## 問題

`--auto-plan`（設計 30）在計畫一停泊時就跨過計畫閘門——而兩個 host 的
自動過閘都丟掉了 `approvePlan` 為人工閘門計算的警示（caveats）：缺少
`### Verification` 小節、堆疊的計畫標題、未驗證的依賴。人類為橡皮章式
的雜務任務啟用這面旗；結果一份沒有 Verification 小節的計畫落地（於是
永遠不會跑任何 discovered check），BUILD 照樣接續。那正是代價要晚整整
一個迭代才付清的計畫缺陷——也正是「不該橡皮章」的那個案例。人工閘門在
決策當下會顯示的警示，沒有任何人看到。

## 改了什麼

- **`planCaveats`（core，`gate.ts`）**把警示清單抽成匯出的純函式——正是
  `approvePlan` 渲染的那份清單，抽出來讓自動過閘可以在核准之前先問
  「人工閘門會不會警告？」。
- **兩個自動過閘的 arm 都先判斷它。**OpenCode 的
  `autoAdvanceParkedPlan` 和 Claude host 的停泊 arm，只要有任何警示就
  拒絕自動過閘：計畫留在 `plan-review/`，旗標留在檔案上（意圖不會丟），
  結果訊息列出警示與出路——手動 `approve <id>` 仍然可以照樣跨過，
  `replan <id> <reason>` 仍然可以退回。
- **朝人工審查方向失敗**，與 gate hook 的 fail-closed 不對稱一致：誤拒
  的代價是對一份值得讀的計畫多打一次 approve；誤放則出貨一個無法驗證的
  迭代。

## 尖銳邊界

- **`--auto-plan` 的意思是「沒有問題可問時跳過提問」**，絕不是「不管計
  畫長什麼樣都跨過」。橡皮章意圖是按「這次 PLAN 的產出」判斷，不是按任
  務——同一個任務下次修訂後的計畫若符合契約，仍會自動跨過。
- **契約乾淨的計畫完全不受影響**——警示防線下的橡皮章路徑與設計 30 出
  貨時逐字節相同（chain 與 no-chain 兩個 arm 都有測試釘住）。
- **拒絕不是駁回。**沒有東西移動、不計 strike、不寫審計註記——停泊註記
  （設計 24）已經帶著契約預覽；這裡只是收回「自動」核准。
